# HW9 frozen experiment plan

Configuration: SID4 0686, PORT_BASE 8686, PREFIX s0686, SEED 686, VERIFY_SEED 260686, DOMAIN_ID 6 (Rental Housing Listings). Extend the existing MySQL s0686_rel application and HW8 Planner/Writer/Reviewer pipeline.

Commit cache_cases.yaml before embedding measurements or threshold sweeps. It contains exactly 40 labeled cases, shuffled with VERIFY_SEED: ten exact duplicates, ten reference-code paraphrases, ten similar reference-code questions about different records, and ten unrelated location/availability questions. The ten exact cases are also the documented warm-up queries. Do not edit labels after observing results. Different record IDs/codes need different answers, even when sentence wording is almost identical.

Use the already installed local nomic-embed-text model and Redis FLOAT32 FLAT vector index with COSINE distance. Similarity is 1 minus Redis cosine distance. Start at 0.85. Run all 40 cases at 0.75, 0.80, 0.85, 0.90, and 0.95 against the same ten frozen warm-up answers obtained from real HW8/local-model misses. Each threshold has a separate s0686 namespace. Do not add case-miss answers to this frozen benchmark cache; normal ingress does add misses. This prevents case-order effects and makes threshold comparisons repeatable. Every benchmark miss still runs the real pipeline. Embedding computation and lookup are included in the measured response latency.

Report hit rate as hits/40 and false-hit rate as wrong cached answers/40; also retain wrong cached answers/hits. Correctness means the returned JSON matches the expected listing ID and requested field from the MySQL facts. A cache miss costs 1 normalized cost unit for recomputation; a false hit costs 20 units for the larger support/correction risk of returning the wrong property's data. These are explicit homework assumptions, not measured dollars. Total = misses + 20*false_hits. Ship the threshold with minimum measured total cost; break ties in favor of the higher threshold.

Part 4 reference facts are a separate snapshot of real rental records. Input files contain only question, listing_id, and requested field names, never expected values. Use training only to demonstrate controlled omission/repair and derive lessons. Use validation to compare a proposed lesson before/after; retain only when no existing correct case regresses, failure-case correctness does not fall, and unrelated/missing facts remain supported or null. Read the held-out test file only for the final four independent runs after lesson selection; never use its outputs to revise the system. No fault injection is used for held-out evaluation.

Keep backups and runtime state private/ignored. Never FLUSHDB. Use only s0686-prefixed Redis keys/indexes, and delete only per-run keys created by these scripts. Restore the staleness demonstration's original MySQL record in a finally block. Report observed results, including failed runs, without inventing a false hit or a speedup.
